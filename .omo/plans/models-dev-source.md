# models-dev-source - Work Plan

## TL;DR (For humans)

**What you'll get.** The generated pricing layer (`src/lib/pricing.generated.json`) will be sourced from `https://models.dev/catalog.json` instead of OpenRouter's `/api/v1/models`. The existing sync architecture is preserved: `npm run sync-models` still fetches and writes the snapshot, `npm run sync-models:check` still detects drift in CI, and `--allow-missing` still carries forward last-known pricing for models the source no longer lists. The editorial layer (`scripts/model-catalog.ts`) is untouched except for a field rename and per-row slug remap. Your app's user-facing `Model` type and `calculateCost` math do not change at all.

**Why this approach.** models.dev publishes prices natively as **USD per 1M tokens** (matches your `PricePerM` shape — zero unit conversion), surfaces `cache_read` / `cache_write` as first-class fields (kills the `KNOWN_CACHE_VENDORS` heuristic and the `0.1×input` cache-price fallback), and exposes `open_weights` as a clean boolean (kills the OpenRouter `inferIsOpen` heuristic). Raw `/catalog.json` via the existing script keeps the pipeline you already understand and the drift gate you already rely on, without adopting a new runtime dependency.

**What it will NOT do.**
- Will NOT refresh the 16-model lineup (no Opus 4.7→5, MiniMax m2.7→M3, GLM-5.1→5.2 bumps). Mismatched rows carry forward last-known pricing and surface as warnings in the sync report; refreshing them is a separate editorial decision.
- Will NOT adopt the `@opencode-ai/models` SDK.
- Will NOT add a runtime fetch in the Next.js app, scheduled Vercel functions, or automated cron.
- Will NOT change any user-facing field name on `Model` (`inputPricePerM`, `outputPricePerM`, `cacheReadPricePerM`, etc. all stay).
- Will NOT touch editorial judgment fields (`tier`, `strengths`, `outputMultiplier`, capability scores).
- Will NOT touch `gpt-tokenizer`, `recommend.ts`, `counterfactual.ts`, `replayHarness.ts`, or any unrelated subsystem.

**Effort.** Standard: ~5 file edits, 1 new types file, 1 new mappers module + tests, 1 regenerated JSON, 2 doc updates. ~1 working day end-to-end.

**Risk.** Low–medium. Main risks: (a) ~5–6 of the 16 editorial rows will not have an exact models.dev canonical id (different lab slug or newer version) → carry-forward engaged, pricing goes stale until a separate lineup-refresh decision; (b) models.dev omits `cache_read` for some providers we previously inferred cache support for → those rows may lose cache pricing; (c) upstream schema drift (community TOML) → mitigated by the preserved `--check` gate. All three risks surface loudly in the sync report and never silently corrupt pricing.

**Decisions locked at the gate.**
1. Source mechanism: **raw `/catalog.json` via `scripts/sync-models.ts`** (no SDK).
2. Pricing source per model: **the lab's own provider entry** (e.g. `providers["anthropic"].models["claude-sonnet-5"].cost`).
3. Slug/version mismatch handling: **carry-forward + warn**; no lineup refresh in this plan.
4. Field rename `openrouterSlug` → `sourceId`, `openRouterEndpoint` → `sourceEndpoint` (announced default).
5. Heuristics dropped: `KNOWN_CACHE_VENDORS`, `0.1×input` cache fallback, OpenRouter `inferProvider`/`inferIsOpen` (announced default).

## Verification strategy

- **Unit tests (agent-executed)**: `npm run test` (vitest). New mapper tests cover every pure function. Existing `recommend.test.ts`, `reconstructCost.test.ts`, `retokenizedCost.test.ts`, etc. must still pass — they reference stable `id` values, not prices, so they are source-swap-invariant by construction. Confirm by running the full suite.
- **Snapshot drift gate (agent-executed)**: after committing the regenerated `pricing.generated.json`, run `npm run sync-models:check` and confirm exit 0 ("Snapshot is up to date."). This is the regression gate that proves the source swap produces a stable, idempotent snapshot.
- **Carry-forward audit (agent-executed)**: read the sync stdout from T8; confirm every unmatched row is listed exactly once under the "Editorial ids not found on models.dev" warning and still appears in the regenerated snapshot with its previous pricing. Zero silent drops.
- **Type-safety gate (agent-executed)**: `npx tsc --noEmit` must pass after the rename — proves the `openrouterSlug → sourceId` rename is exhaustive across all 4 files.
- **Manual QA (agent-executed, optional but recommended)**: `npm run dev`, open `http://localhost:3000`, confirm the lineup renders, prices display, and the calculator produces non-zero totals for at least one frontier model (Claude Opus 4.7) and one carried-forward model. Screenshot evidence path documented in T10.

## Execution strategy

Five sequential waves. **The rename is staged BEFORE the source swap** so every wave boundary leaves the repo in a tsc-clean, test-green, functionally-working state — no half-broken intermediate commits.

- **Wave 1 — Additive foundation**: T1 (remap analysis, new doc only) + T2 (new types file). Zero edits to existing product files. Repo state after wave 1: unchanged behavior, two new artifacts.
- **Wave 2 — Logic-preserving rename**: R1 (combined T6-rename + T7-rename). Renames `openrouterSlug`→`sourceId` in editorial type + all 16 rows (values unchanged — still OpenRouter slugs), updates sync-models.ts to read `entry.sourceId` (still hits OpenRouter), renames snapshot fields in models.ts. Repo state after wave 2: tsc clean, `npm run sync-models` still works against OpenRouter, app renders identically. This wave exists purely so wave 3 can swap source logic without simultaneously renaming fields.
- **Wave 3 — Source swap + tests**: T3 (sync rewrite: /catalog.json, new mapping, drop heuristics), T4 (extract mappers), T5 (mapper tests). T3 leaves the editorial `sourceId` values still pointing at OpenRouter slugs → most rows will fail to resolve on /catalog.json and carry forward; that's expected mid-wave.
- **Wave 4 — Apply remap + regenerate + docs**: T6-values (populate each row's `sourceId` from the T1 remap table), T8 (regenerate snapshot), T9 (docs).
- **Wave 5 — Final verification**: F1–F4 in parallel, all must APPROVE.

Dependency chain: T1 blocks T6-values (wave 4). T2 blocks T3 + T4 (wave 3). R1 (wave 2) blocks T3 (sync reads `entry.sourceId`). T3 blocks T4 (mappers extracted from T3's logic). T4 blocks T5. T6-values + T3 block T8 (regen needs new slugs AND new source logic). T8 blocks T9 (docs cite post-regen state). All of waves 1–4 block F1–F4.

The biggest single risk is concentrated in **T1** (the remap verification) — that is why it is wave 1, alone, with a precise deliverable.
